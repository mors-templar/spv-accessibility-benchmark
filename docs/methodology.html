Working proposal

How the study is being designed.

The goal is to compare generated websites using the same tasks and clearly defined accessibility checks.

Not yet finalized: Conditions, run counts, measurements, and analysis will be reviewed before the study begins.

Generate separate websites

The proposed comparison includes a baseline, a simple accessibility checklist, prompt guidance, a skill, a validation agent, and a combined configuration. The same task request would be used for every condition.

Evaluate behavior and accessibility

Proposed checks include task functionality, browser-based tests, and human review of keyboard use, focus, labels, and content. The exact checks depend on the task and the controls created.

Automated checks detect some accessibility issues; they cannot establish complete accessibility or WCAG conformance. The W3C and Playwright describe these limitations.

Keep the evidence separate

Each attempted run should retain its configuration, generated artifact, test outcomes, and applicable limitations. Failed or incomplete runs should remain visible.

Research foundations

  • CodeA11y, CHI 2025: accessibility assistance for developers using AI coding tools.
  • Cognitive forcing functions, CSCW 2021: an experiment on human decisions with AI assistance.
  • ProjectEval, ACL Findings 2025: project-level evaluation using simulated interactions.

These studies inform the design. They do not establish the outcome of this study.
